## TL;DR

Phase 1 of the AIWS Skill Library is shipped. A Google Drive folder shaped as a Skill Library can be installed in Cowork as a plugin-like container, refreshed when canonical changes, and updated through a propose-and-accept lifecycle without ZIP uploads, marketplace tooling, or per-skill manifests. The end-to-end 10-step demo passes; documentation, testing manual, and audience-facing demo script are pushed to the repo. Three known upstream skill issues are queued as the first Phase 2 work item.

## What shipped in Phase 1

**Capability**: Team members can keep a shared library of skills in a Google Drive folder, install it into Cowork, propose changes through a transparent diff-based review process, and refresh installed skills as the library evolves. The library is portable: the same skill folder is consumable by Cowork, Claude Code, and Codex (Cowork validated; cross-host validation deferred to Phase 2).

**Concrete deliverables**:

- `core-aiws` v0.5.0 plugin with seven Drive-library lifecycle skills (install, refresh, validate, check, update, propose, improve).
- 10-step end-to-end demo against a real Test Plugin Drive library on Google Drive, all steps passing.
- Testing manual (`docs/aiws-skill-library-phase1-testing-manual.md`, ~600 lines) — engineering-grade walkthrough with pass/fail criteria, anti-pattern guards, recovery prompts, role boundaries, persistence caveats, and an SOP audit table.
- Demo script (`docs/aiws-skill-library-phase1-demo-script.md`, ~250 lines) — presenter-facing 10-section walkthrough with verbatim prompts.
- Process diagram on Miro: [AIWS Skill Library Phase 1 — Testing Scenario](https://miro.com/app/board/uXjVHNBbn_8=/).
- All commits authored as `athanasiosbot`, pushed to `sashakang/ai-workspace` master.

**Key design decisions that landed**:

- Google Drive folder is the source of truth, not Cowork's plugin store.
- AIWS only enters on explicit user intent (install, propose, refresh, validate). Authoring and using a local skill never touch AIWS.
- Maintainer review uses local Markdown diff (VS Code / Meld); no Google Docs compare in Phase 1.
- Approved/Rejected folders are optional recordkeeping; partial-accept is handled by direct canonical edit and proposal-folder deletion.
- Save plugin (multi-skill `.plugin`) and Save skill (single `.skill`) are routed by source artifact, not button name — this guard is encoded in the install skill and verified in core-aiws 0.4.21 (commit `5bd2147`).

## Phase 1 work that fell outside the original plan

While walking the demo, several latent issues surfaced and were fixed in-flight:

- **SOP audit**: an audit of all seven AIWS Drive-library skills found hard-coded library and skill names that would cause stale-preflight failures whenever the demo baseline changed. Fixed across all skills (commit `8e037cc` and successors) and committed to the AIWS source repo. SOP documented in the testing manual.
- **Cowork persistence asymmetry**: plugins are filesystem-driven (file delete works after Cowork quit or UI uninstall); local user skills are in-memory-driven (only Cowork's UI removal survives the quit-write). Documented in the testing manual's reset and cleanup sections.
- **Role boundaries**: maintainer-accept is a deliberate human action; the assistant must not auto-execute it after a propose. Encoded in Steps 4.3 and 9 of the testing manual.

## Open items carried to Phase 2

### Phase 2 priority 1 (next): Upstream skill fixes

Three concrete fixes filed against the AIWS skills. Estimated work: half a day.

1. `aiws-refresh-skill-library` — add the anti-marketplace-fallback guard that `aiws-install-drive-skill-library` already has. Currently the refresh skill misroutes through AIWS marketplace indexing and reports `NEEDS MANUAL ACTION` against any Drive library that isn't also a marketplace. The fix mirrors the install skill's guidance: read Drive directly, treat empty marketplace indexing as expected.
2. `aiws-propose-skill-update` — remove the maintainer-side instruction to update `contracts/<plugin-id>.contract.json`. That file is auto-generated by the install/refresh artifact builder and must not be edited on Drive.
3. `aiws-install-drive-skill-library` — boundary tightening: explicitly reject a Drive root that contains `.claude-plugin/` or `contracts/` as "not a Drive Skill Library", instead of silently packaging just the `skills/` subset.
